# FR §4.10 — Programmatic and Command-Line Access

*States that the system is reachable at all. §4.1–§4.9 say what happens once a caller is inside; this group says there is a way in, and that it is one way rather than two diverging ones.*
*Source: MANIFESTO Principle 28; ADR-015, ADR-016.*
*Use Cases: UC-01 – UC-06.*

---

This group was written late, and the reason is worth recording. The Public API + CLI container
is in V1 scope (SRS §1.4) and its surface has been defined normatively since the technical
contracts were written: `04-public-api-contract.md` fixes the function signatures and
`02-cli-spec.md` fixes the commands, which ADR-016 makes authoritative. What was missing was any
requirement stating that the system offers them. The C3 components cited FR-28 and FR-29 for it;
those identifiers had been reassigned to Study Design Guidance, so the citation had been wrong
since the renumbering and nothing detected it, because a container with no requirement behind it
looks exactly like a container whose requirement is elsewhere.

Nothing here is new policy. Each requirement below promotes a decision already recorded in a
normative document to the layer that decides what V1 contains. The contracts remain the
authority on signatures, command names, options and exit-code values; this group is the
authority on whether those surfaces must exist.

---

## FR-39

**The system MUST expose every V1 operation as a Python function in the `corvus_corone` public namespace. The set of functions, their signatures, parameter names, defaults, return types and raised exceptions are those of `docs/03-technical-contracts/04-public-api-contract.md`, and the facade MUST expose no public function absent from it.**

- **Priority:** MUST
- **Source:** MANIFESTO Principle 28; SRS §1.4 (Public API + CLI is a V1 container)
- **Accepted when:** A test enumerates the public names of `corvus_corone` and asserts set equality with the functions listed in `04-public-api-contract.md` — equality, not containment, so that an extra undocumented function fails as loudly as a missing documented one. Every V1 use case, UC-01 through UC-06, is executable through those functions alone.
- Connects to: `docs/03-technical-contracts/04-public-api-contract.md`; `docs/02-design/02-architecture/03-c4-leve2-containers/04-c4-leve3-components/10-public-api-cli/01-index.md`

## FR-40

**The system MUST provide a `corvus` command-line tool covering the operations named in `docs/02-design/02-architecture/03-c4-leve2-containers/02-cli-spec.md`. Every command MUST delegate to a function of the Python facade and MUST NOT expose any capability the facade lacks. The command line is a subset of the facade, not a parallel surface: Study authoring has no command-line form in V1.**

- **Priority:** MUST
- **Source:** ADR-016
- **Accepted when:** Each command in `02-cli-spec.md` §Commands resolves to a `cc.*` function in the mapping table of that document, and a test asserts the CLI defines no command whose behaviour is not reachable through the facade. A capability offered only on the command line is a defect, because it would be untestable from the API surface and unreachable from a notebook.
- Connects to: `docs/02-design/02-architecture/01-adr/adr-016-cli-surface-authority.md`; `docs/02-design/02-architecture/03-c4-leve2-containers/02-cli-spec.md`; `docs/02-design/02-architecture/03-c4-leve2-containers/04-c4-leve3-components/10-public-api-cli/01-index.md`

## FR-41

**Command-line output MUST remain consumable by a script. Results MUST go to stdout; progress indicators, warnings and error messages MUST go to stderr. Every error message MUST begin with the exception class name from the ADR-015 taxonomy, so that a caller can identify the failure category without parsing the human-readable remainder.**

- **Priority:** MUST
- **Source:** MANIFESTO Principle 28; ADR-015
- **Accepted when:** For each command, a test captures the two streams separately and asserts that stdout holds only the result and that no progress or diagnostic text reaches it. For each class in the error taxonomy of `02-interface-contracts/07-cross-cutting-contracts.md` §6 that the CLI can raise, a test asserts that stderr matches `Error: <ClassName>: `.
- Connects to: `docs/02-design/02-architecture/03-c4-leve2-containers/02-cli-spec.md` §Common Conventions; `docs/03-technical-contracts/02-interface-contracts/07-cross-cutting-contracts.md`

## FR-42

**A command MUST signal its outcome through its exit code, and the codes MUST distinguish failure categories rather than collapsing them into a single non-zero value. The mapping from exception class to exit code is the table in `02-cli-spec.md` §Exit codes.**

- **Priority:** MUST
- **Source:** ADR-015, ADR-016
- **Accepted when:** A test drives each documented failure category and asserts the exit code the table gives, including the case the table calls out explicitly: an Experiment in which individual Runs failed exits `0`, because a failed Run is a recorded scientific outcome (FR-12) and not a failure of the command. Only a whole-Experiment failure produces a non-zero code.
- Connects to: `docs/02-design/02-architecture/03-c4-leve2-containers/02-cli-spec.md` §Exit codes; `docs/02-design/02-architecture/01-adr/adr-015-exception-hierarchy-authority.md`
