# FR §4.8 — Study Design Guidance

*Makes the system state what a scientifically sound Study requires, rather than only rejecting one that lacks it. This group operationalizes the second half of the system's purpose: a framework that eases the writing of experiments while holding the scientific line. The first half, enforcement, is covered by §4.1–§4.7.*
*Source: MANIFESTO Principles 1, 16, 25, 28; ADR-021.*
*Use Cases: UC-01.*

---

The requirements in §4.1–§4.7 state what the system must refuse. This group states what it must
tell the researcher instead of merely refusing. Both halves are load-bearing: a framework that
enforces pre-registration without saying what a pre-registration needs is the obstacle that
MANIFESTO Principle 28 and the Researcher success criterion in `02-use-cases/01-index.md`
explicitly rule out.

All five requirements are deterministic library behaviour. The conversational form of the same
function, the Socratic Guide, belongs to Corvus Pilot and is outside V1 (SRS §1, V1 Release
Scope).

---

## FR-27

**When `lock_study()` cannot proceed, the system MUST report every unresolved design decision in a single response, not the first one encountered. Each reported item MUST name the decision, the consequence of leaving it unmade, and the admissible values.**

- **Priority:** MUST
- **Source:** MANIFESTO Principles 16, 28
- **Accepted when:** A Study with three unresolved decisions produces one `ValidationError` naming all three, not three successive rejections. For a Study whose hypotheses reference `TIME-EVALUATIONS_TO_TARGET` with no target specified, the message names the metric that cannot be computed, not only the missing field.
- Connects to: `docs/02-design/01-software-requirement-specification/02-use-cases/02-uc-01.md`; `docs/02-design/02-architecture/01-adr/adr-021-pre-registered-hypotheses-mandatory.md`; `docs/03-technical-contracts/04-public-api-contract.md` `cc.lock_study()`

## FR-28

**Parameters with methodological consequences MUST NOT carry silent default values. `seed_strategy` and `sampling_strategy` are required arguments of `create_study()`. Default values remain permitted for parameters that do not change what the experiment measures.**

- **Priority:** MUST
- **Source:** MANIFESTO Principles 16, 19
- **Accepted when:** `cc.create_study()` without `seed_strategy` or `sampling_strategy` raises `ValidationError`. A review of the `create_study()` signature shows no default value on any parameter that alters what is measured; `log_scale_schedule` internals retain their defaults because they refine a schedule the researcher has already chosen.
- Connects to: `docs/03-technical-contracts/04-public-api-contract.md` `cc.create_study()`; `docs/03-technical-contracts/01-data-format/04-study.md` §2.3

## FR-29

**Every validation error message MUST name the requirement, MANIFESTO principle, or ADR that it enforces.**

- **Priority:** MUST
- **Source:** MANIFESTO Principle 28
- **Accepted when:** For every class in the error taxonomy of `02-interface-contracts/07-cross-cutting-contracts.md` §6, a test asserts that the raised message contains a reference to the rule being enforced. A message of the form "field X is required", carrying no reason, fails the test.
- Connects to: `docs/03-technical-contracts/02-interface-contracts/07-cross-cutting-contracts.md` §6; `docs/02-design/02-architecture/03-c4-leve2-containers/02-cli-spec.md`

## FR-30

**At `lock_study()` the system MUST name the axis of the ADR-009 diversity floor that falls short, and MUST state what the researcher can do about it: add instances, or declare the Study exploratory. The message is guidance regardless of whether the outcome is a rejection (FR-32, FR-33) or, for an exploratory Study, a recorded limitation.**

- **Priority:** MUST
- **Source:** MANIFESTO Principles 4, 5, 28; ADR-009
- **Accepted when:** A Study with five Problem Instances confined to one dimensionality range is rejected at `lock_study()` with a message that names dimensionality as the deficient axis, states the ADR-009 rule, and offers both remedies. The same Study declared exploratory locks successfully, and the shortfall appears verbatim in the limitations section of both generated Reports.
- Connects to: `docs/02-design/02-architecture/01-adr/adr-009-problem-instance-diversity-requirements.md`; `docs/03-technical-contracts/01-data-format/09-report.md`

## FR-31

**The system MUST allow a Study to be declared exploratory, by a hypothesis whose `test_type` is `none`, and MUST carry that declaration into the scope statement of both generated Reports.**

- **Priority:** MUST
- **Source:** MANIFESTO Principles 3, 13; ADR-021
- **Accepted when:** A Study locked with a single `test_type: "none"` hypothesis produces Reports containing a scope sentence stating that the results are exploratory and not confirmatory. No `StatisticalTestResult` in such a Study carries `pre_registered: true`.
- Connects to: `docs/02-design/02-architecture/01-adr/adr-021-pre-registered-hypotheses-mandatory.md`; `docs/04-scientific-practice/01-methodology/02-statistical-methodology.md` §1, §7; `docs/03-technical-contracts/02-interface-contracts/05-analyzer-interface.md`
